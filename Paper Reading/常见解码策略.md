大模型在自回归生成时，每一步都会根据当前上下文输出一个词表概率分布：
$$
[
p(y_t \mid y_{<t}, x)
]
$$
**解码策略**决定了如何从这个分布中选择下一个 token。它不是模型结构的一部分：同一个模型可以在不同任务中切换不同策略。

例如，Qwen2.5、Llama、GPT 系列模型既可以使用 greedy decoding，也可以使用 top-p sampling；策略通常由推理参数控制。Hugging Face 的 `generate()` 接口也将 greedy search、sampling、beam search、contrastive search 和 speculative decoding 等策略统一封装为可配置选项。([Hugging Face][1])

---

# 一、最常用的三类基础策略

## 1. Greedy Decoding：贪心解码

### 核心思想

在每一步直接选择概率最高的 token：
$$
[
y_t = \arg\max_{v \in \mathcal{V}} p(v \mid y_{<t}, x)
]
$$
假设模型预测下一个 token 的概率为：

| token  |   概率 |
| ------ | ---: |
| `cat`  | 0.50 |
| `dog`  | 0.25 |
| `bird` | 0.15 |
| 其他     | 0.10 |

贪心解码永远选择 `cat`。

### 优点

速度快，额外计算量小；相同输入通常得到相同输出；适合需要稳定复现的实验。

### 缺点

它只关注当前一步，没有考虑整段序列的全局质量。某一步选择局部最优 token 后，后续可能进入不理想的生成路径。

### 典型应用与代表模型

贪心解码常用于：

* 分类式问答、信息抽取和格式严格的 JSON 输出；
* VQA 中答案较短、歧义较小的任务；
* VLA 中动作 token 的确定性预测；
* 需要可复现结果的消融实验。

几乎所有自回归模型都可以使用它，包括 **GPT、Llama、Qwen、Gemma、Mistral、BLIP-2、Qwen2.5-VL 和 OpenVLA** 等。这里的含义是“可以使用”，而不是这些模型只能使用贪心解码。

在 Hugging Face 中：

```python
outputs = model.generate(
    **inputs,
    do_sample=False,
    num_beams=1,
)
```

---

## 2. Beam Search：束搜索

### 核心思想

Greedy decoding 每一步只保留一个候选序列。Beam search 则在每一步保留概率最高的 (B) 个候选序列，其中 (B) 称为 `beam size` 或 `num_beams`。

假设第一步有三个候选：

| 候选序列      | 当前累计概率 |
| --------- | -----: |
| `The cat` |   0.50 |
| `The dog` |   0.30 |
| `A bird`  |   0.20 |

当 `num_beams=2` 时，只保留前两个候选。下一步分别扩展这两条路径，再从所有新路径中选择得分最高的两个。

因此，beam search 不会因为某个 token 在单步概率上略低，就立即放弃整个路径。Hugging Face 的官方说明也将它描述为：在每一步追踪多个候选序列，最终选择整体概率较高的结果。([Hugging Face][2])

### 优点

相较于 greedy decoding，它更接近“整段序列层面”的最优结果。对于目标答案相对确定的任务，通常表现较好。

### 缺点

计算和显存开销大致随 `num_beams` 增加；生成结果容易趋向保守、模板化；在开放式聊天或创意写作中，较大的 beam size 可能使文本变得平淡，甚至出现重复。

### 典型应用与代表模型

Beam search 在下列任务中较常见：

* 机器翻译：**T5、mT5、BART、mBART、MarianMT**；
* 文本摘要：**BART、PEGASUS、T5**；
* 图像描述：**BLIP、BLIP-2、InstructBLIP**；
* 语音识别：部分 **Whisper** 推理配置。

例如，Hugging Face 提供的 InstructBLIP 示例使用了 `do_sample=False, num_beams=5`，即 beam search。([Hugging Face][3])

```python
outputs = model.generate(
    **inputs,
    do_sample=False,
    num_beams=5,
)
```

---

## 3. Sampling：随机采样

### 核心思想

不直接选择概率最大的 token，而是按照模型给出的概率分布随机抽样：
$$
[
y_t \sim p(\cdot \mid y_{<t}, x)
]
$$
仍然考虑前面的例子：

| token  |   概率 |
| ------ | ---: |
| `cat`  | 0.50 |
| `dog`  | 0.25 |
| `bird` | 0.15 |
| 其他     | 0.10 |

随机采样时，`cat` 最容易被选中，但 `dog` 和 `bird` 也有机会出现。

Hugging Face 将这种方式称为 multinomial sampling 或 ancestral sampling。([Hugging Face][4])

### 优点

输出更加多样，适合开放式聊天、创意写作和生成多个候选答案。

### 缺点

低概率 token 也可能被选中。直接在整个词表上采样时，模型容易生成不连贯、跑题或带有幻觉的内容。

因此，实际使用中很少只使用“原始随机采样”，而是搭配 `temperature`、`top-k` 和 `top-p` 等参数。

```python
outputs = model.generate(
    **inputs,
    do_sample=True,
    num_beams=1,
)
```

# 二、最常见的采样控制方法

严格来说，`temperature`、`top-k` 和 `top-p` 不是完全独立的解码框架，而是对 sampling 的概率分布进行修正。它们经常组合使用。

## 4. Temperature Scaling：温度缩放

### 核心思想

在 softmax 前，用温度参数 (T) 调整 logits：
$$
[
p_i =
\frac{\exp(z_i / T)}
{\sum_j \exp(z_j / T)}
]
$$
其中 $z_i$ 是 token $i$ 的原始 logit。

### 直观理解

| 温度      | 概率分布变化   | 输出特点    |
| ------- | -------- | ------- |
| (T < 1) | 概率分布更加尖锐 | 更稳定、更保守 |
| (T = 1) | 保持原始分布   | 正常采样    |
| (T > 1) | 概率分布更加平坦 | 更多样、更随机 |

假设原本的概率为：

| token  | 原始概率 |
| ------ | ---: |
| `cat`  | 0.70 |
| `dog`  | 0.20 |
| `bird` | 0.10 |

降低 temperature 后，`cat` 的优势会进一步扩大；提高 temperature 后，`dog` 和 `bird` 更容易被抽中。

### 典型应用与代表模型

Temperature 广泛用于 GPT 风格的聊天模型和开放式生成模型，例如 **GPT 系列、Llama、Qwen、Mistral、Gemma、DeepSeek** 等。

需要注意：当 `do_sample=False` 时，降低 temperature 通常没有实际意义，因为模型依然直接执行 `argmax`。

```python
outputs = model.generate(
    **inputs,
    do_sample=True,
    temperature=0.7,
)
```

---

## 5. Top-k Sampling

### 核心思想

只保留概率最高的 (k) 个 token，然后在这 (k) 个 token 中重新归一化并随机采样。

假设：

| token  |   概率 |
| ------ | ---: |
| `cat`  | 0.40 |
| `dog`  | 0.25 |
| `bird` | 0.15 |
| `fish` | 0.10 |
| `tree` | 0.06 |
| `car`  | 0.04 |

当 `top_k=3` 时，只保留：

| token  | 原始概率 |
| ------ | ---: |
| `cat`  | 0.40 |
| `dog`  | 0.25 |
| `bird` | 0.15 |

其他 token 的概率直接置零，再对保留下来的概率重新归一化。

### 优点

可以排除概率极低、通常不可靠的 token，减少胡言乱语。

### 缺点

固定的 (k) 不够灵活：

* 当模型非常确定时，可能只需要保留 2 个候选；
* 当模型面对开放式问题时，合理候选可能远超 20 个。

### 典型应用与代表模型

Top-k 常用于开放式文本生成和聊天模型，例如 **GPT-2、Llama、Qwen、Mistral 和 Gemma** 等。

Qwen2.5-72B-Instruct 的公开生成配置中使用了 `top_k=20`，同时搭配 `temperature=0.7` 和 `top_p=0.8`。([Hugging Face][5])

```python
outputs = model.generate(
    **inputs,
    do_sample=True,
    top_k=20,
)
```

---

## 6. Top-p Sampling：核采样或 Nucleus Sampling

### 核心思想

从概率最高的 token 开始累加，只保留累计概率达到阈值 (p) 的最小 token 集合，然后在其中采样。

假设：

| token  |   概率 | 累计概率 |
| ------ | ---: | ---: |
| `cat`  | 0.40 | 0.40 |
| `dog`  | 0.25 | 0.65 |
| `bird` | 0.15 | 0.80 |
| `fish` | 0.10 | 0.90 |
| `tree` | 0.06 | 0.96 |
| `car`  | 0.04 | 1.00 |

当 `top_p=0.80` 时，只保留前三个 token。

### 与 top-k 的关键区别

* `top-k`：候选数量固定；
* `top-p`：候选总概率固定，候选数量动态变化。

当模型非常确定时，top-p 可能只保留少数 token；当模型不确定时，它会自动允许更多候选。

Nucleus sampling 由 Holtzman 等人提出，主要目的就是截断概率分布中不可靠的长尾部分，同时保留生成多样性。([arXiv][6])

### 典型应用与代表模型

Top-p 是现代聊天模型最常见的采样方法之一，常见于 **GPT 系列、Llama、Qwen、Mistral、Gemma 和 DeepSeek** 等模型的推理配置。

例如，Qwen2.5-72B-Instruct 的默认生成配置采用：

```python
temperature = 0.7
top_p = 0.8
top_k = 20
repetition_penalty = 1.05
```

这意味着模型不是只使用一种策略，而是同时使用多种概率约束。([Hugging Face][5])

---

## 7. Min-p Sampling

### 核心思想

以当前最高概率 token 为基准，过滤掉相对概率过低的 token。

假设最高概率为：

$$
[
p_{\max}=0.60
]
$$

若设置：

$$
[
min_p=0.10
]
$$
则只保留满足下式的 token：

$$
[
p_i \geq 0.10 \times 0.60 = 0.06
]
$$

### 特点

Min-p 与 top-p 类似，都是为了排除不可靠的长尾 token；区别在于 min-p 使用“相对于最高概率”的阈值，而不是累计概率阈值。

### 典型应用与代表模型

Min-p 是较新的扩展策略，在部分新模型的推荐推理参数中开始出现。例如，Qwen3.5 的公开模型卡给出了包含 `temperature`、`top_p`、`top_k` 和 `min_p` 的推荐采样配置。([Hugging Face][7])

它目前更适合作为可选调参项，而不是替代 top-p 的默认首选。

# 三、基础策略的组合与变体

## 8. Beam Sampling：束搜索采样

### 核心思想

将 beam search 和 sampling 结合起来：

* 同时保留多个候选序列；
* 扩展候选时不完全依赖最高概率 token，而是进行随机采样。

它兼顾一定程度的全局搜索能力和输出多样性。

在 Hugging Face 中，设置 `num_beams > 1` 且 `do_sample=True` 即可启用 beam-search multinomial sampling。([Hugging Face][8])

```python
outputs = model.generate(
    **inputs,
    num_beams=4,
    do_sample=True,
    top_p=0.9,
)
```

### 典型应用

适合一次生成多个质量较高但又不完全相同的候选，例如：

* 图像描述候选；
* 翻译候选；
* 数据增强；
* 候选答案生成后再由 verifier 或 reward model 筛选。

---

## 9. Diverse Beam Search：多样化束搜索

### 核心思想

普通 beam search 的多个候选经常高度相似。Diverse beam search 会将 beams 分组，并加入多样性惩罚，使不同组探索不同生成方向。

它最早被用于图像描述、机器翻译和视觉问题生成等任务。([arXiv][9])

### 典型应用与代表模型

常见于：

* 图像描述模型：**BLIP、ViT-GPT2** 等；
* 翻译与摘要模型：**T5、BART** 等；
* 需要生成多个差异化候选的系统。

```python
outputs = model.generate(
    **inputs,
    num_beams=8,
    num_beam_groups=4,
    diversity_penalty=1.0,
)
```

# 四、更加高级的解码策略

## 10. Contrastive Search：对比搜索

### 核心思想

Contrastive search 不仅考虑候选 token 的概率，还会惩罚与历史 token 表示过于相似的候选，从而减少重复和退化。

可以将其抽象为：

$$
\operatorname{score}(v)
=
(1-\alpha)\cdot \log p(v)
-
\alpha \cdot \operatorname{degeneration\_penalty}(v)
$$

第一项鼓励生成高概率 token；第二项惩罚重复、模板化或表示过度相似的内容。

### 典型应用与代表模型

适合长文本续写和开放式生成。其代表性工作是 **SimCTG**，论文提出 contrastive search 来兼顾流畅性与多样性。([arXiv][10])

Hugging Face 也原生支持 contrastive search。典型调用方式为：([Hugging Face][11])

```python
outputs = model.generate(
    **inputs,
    penalty_alpha=0.6,
    top_k=4,
)
```

可应用于 **GPT-2、OPT、Llama** 等自回归语言模型，但在主流聊天系统中，它不如 top-p sampling 普及。

---

## 11. Contrastive Decoding：对比解码

Contrastive decoding 与 contrastive search 名字相近，但不是同一种方法。

### 核心思想

同时使用两个模型：

* **expert model**：较大的模型；
* **amateur model**：较小的模型。

选择 token 时，不只看大模型的概率，还考察大模型与小模型之间的差异：

$$
\operatorname{score}(v)
=
\log p_{\mathrm{expert}}(v)
-
\lambda \log p_{\mathrm{amateur}}(v)
$$

如果某个 token 连小模型也很容易生成，它可能是模板化、平庸或容易出错的选项。对比解码倾向于选择“大模型明显更加认可”的 token。

### 代表模型

原论文使用的代表性组合包括：

* **OPT-13B** 作为 expert，**OPT-125M** 作为 amateur；
* **GPT-2 1.5B** 与较小 GPT-2 模型的组合。

该方法无需重新训练模型，但每一步至少要运行两个模型，因此会增加推理开销。([arXiv][12])

---

## 12. Constrained Decoding：约束解码

### 核心思想

在每一步生成 token 时，先排除所有不符合规则的 token，只允许模型在合法 token 中选择。

例如，要求模型必须输出：

```json
{
  "object": "cup",
  "color": "red"
}
```

那么当模型生成到字段名位置时，可以限制它只能输出 JSON Schema 中允许的字段；当生成枚举值时，只允许输出规定选项。

### 典型应用与代表系统

约束解码广泛用于：

* JSON Schema 输出；
* 函数调用和工具调用；
* SQL、代码和正则格式生成；
* 语法树生成；
* 机器人动作空间约束；
* 医疗、金融等高可靠输出场景。

OpenAI 的 Structured Outputs 会根据开发者提供的 JSON Schema 约束模型生成结果，以减少遗漏字段、非法枚举值和格式错误。([OpenAI][13])

在你的 BridgeLang 场景中，约束解码尤其重要：它可以保障 `FACT_LIST` 和 `desc_text` 的结构合法性，但不能单独保证视觉事实本身没有幻觉。事实正确性仍然需要视觉 verifier 检查。

---

# 五、容易与“解码策略”混淆的方法

## 13. Speculative Decoding：推测解码

### 核心思想

先让一个小型 draft model 连续生成若干 token，再让大型 target model 一次性验证这些 token：

1. 小模型快速起草多个 token；
2. 大模型并行检查；
3. 接受符合目标分布的部分；
4. 从不符合的位置重新生成。

### 它解决的问题

Speculative decoding 主要用于**降低推理延迟**，而不是改变输出风格。理论上，它可以在保持目标模型输出分布不变的情况下加速生成。

代表性论文在 T5-XXL 上展示了约 2–3 倍加速，并且输出保持一致。([arXiv][14])

### 典型模型组合

* 小型 Llama + 大型 Llama；
* 小型 Qwen + 大型 Qwen；
* 小型 draft model + 任意兼容的 target model；
* 原始论文中的 **T5-XXL** 和 **LaMDA** 场景。

它可以与 greedy、top-p 或其他采样策略组合使用，因为它是推理加速机制，而不是内容选择偏好的替代品。

---

## 14. Repetition Penalty、No-repeat N-gram 等修正项

这些也不是完整的解码策略，而是 logits 修正方法。

### Repetition Penalty

降低已经出现过的 token 再次出现的概率：

```python
repetition_penalty=1.05
```

### No-repeat N-gram

禁止重复出现长度为 (n) 的相同片段：

```python
no_repeat_ngram_size=3
```

### Length Penalty

在 beam search 中调整模型对长序列和短序列的偏好：

```python
length_penalty=1.0
```

这些参数常与 beam search 或 sampling 联合使用。

# 七、不同任务应该怎样选择？

## 1. 普通聊天机器人

常见配置：

```python
do_sample=True
temperature=0.6
top_p=0.9
top_k=20
```

原因是聊天任务不存在唯一答案，需要适度多样性。

---

## 2. 代码生成、数学推理或事实问答

可以降低随机性：

```python
do_sample=True
temperature=0.1
top_p=0.9
```

或者直接使用：

```python
do_sample=False
```

如果需要生成多个候选后进行验证，可以低温采样多次，再由测试用例或 verifier 选择结果。

---

## 3. 翻译与摘要

优先考虑 beam search：

```python
do_sample=False
num_beams=4
length_penalty=1.0
```

因为输出目标相对明确，追求稳定性通常比追求多样性更重要。

---

## 4. 图像描述

有两种常见选择：

* 需要稳定描述：beam search；
* 需要多个差异化描述：top-p sampling 或 diverse beam search。

---

## 5. VLA 动作预测

通常优先使用 greedy decoding 或低随机性策略。

对于机器人控制，随机抽到一个概率较低的动作 token 可能带来实际风险。若确实需要探索，通常也应在仿真环境、规划器或 safety checker 的约束下进行，而不是直接依赖高温采样。

---

# 八、最重要的理解

实际的大模型推理通常不是“从多个策略中只选一个”，而是采用组合：

$$
[
\text{Sampling}
+
\text{Temperature}
+
\text{Top-k}
+
\text{Top-p}
+
\text{Repetition Penalty}
]
$$

例如，Qwen2.5-72B-Instruct 的公开配置就是：

```python
do_sample=True
temperature=0.7
top_p=0.8
top_k=20
repetition_penalty=1.05
```

([Hugging Face][5])

因此，可以把常见解码策略概括为四层：

1. **基础决策方式**：greedy、beam search 或 sampling；
2. **概率过滤方式**：temperature、top-k、top-p、min-p；
3. **输出约束方式**：JSON Schema、grammar、重复惩罚；
4. **推理加速方式**：speculative decoding。

其中，对于现代聊天模型，最常见的是 **temperature + top-p sampling**；对于翻译和摘要，beam search 仍然常见；对于稳定动作预测与严格格式输出，greedy decoding 或 constrained decoding 更合适。
